# ビジネスモデル：収益構造・ROI・KPI算定式

> PRD §3.1 の詳細定義。評価軸3（ビジネス成立性）への回答であり、ダッシュボードKPI「推定削減コスト」の**唯一の算定根拠**でもある。

> ⚠️ **本ドキュメントの数値は現時点ですべて仮説**である。各表の「ステータス」列で検証状況を管理し、確定していない値をピッチで断定形にしない。

- 作成日: 2026-08-10
- 対象: 評価軸3（ビジネス成立性）／FR-6・KPI表示の実装根拠

## 1. 誰が・誰に・いくら払うのか

### 1.1 取引構造

| 役割 | 主体 | 補足 |
|---|---|---|
| **売り手** | 本プロダクト提供事業者 | ハードウェア＋SaaSの一体提供 |
| **買い手** | 水道事業体（市町村の水道局・企業団） | 民間の保守業者ではなく**事業体が直接の契約主体** |
| **予算費目** | **水道事業会計**（公営企業会計） | 一般会計ではない。独立採算のため費用対効果の説明が必須 |
| **意思決定者** | 水道事業管理者・施設課長クラス | 導入判断は「漏水調査委託費の代替になるか」で行われる |
| **利用者** | 管路管理担当者、委託先の漏水調査事業者 | 日常のダッシュボード操作者 |

### 1.2 価格構造（仮説）

| 項目 | 単価 | 課金タイミング | ステータス |
|---|---|---|---|
| センサー本体 | ¥20,000 / 台 | 初期 | **仮説** — PRD §3 の「2万円モデル」に準拠。量産前提の目標原価 |
| 設置費 | ¥5,000 / 台 | 初期 | **仮説** — 消火栓貼付型のため掘削不要。既存の点検巡回に同行して設置する想定 |
| SaaS利用料 | ¥800 / 台 / 月 | 月額 | **仮説** — 通信費・解析基盤・保守を含む |
| LLM自動起票 | ¥50 / 起票 | 従量（オプション） | **仮説** — 実測原価は `llm-cost.md` 参照。原価に対する妥当なマージンで再設定する |

### 1.3 導入経路

自治体調達の現実（単年度予算・入札）に合わせ、2段階で入る。

```
[Phase 1] 実証事業（1年）
  規模: 50台 / 重点監視区間（過去の漏水多発エリア）
  目的: 有収率の改善幅を実データで示す
  金額: 初期 ¥1,250,000 + 月額 ¥480,000/年 = 約 ¥173万/年
        └ 少額随意契約または実証事業予算の範囲に収める設計
        ▼ 効果検証（有収率・調査工数の実績比較）
[Phase 2] 本格導入（複数年）
  規模: 1,000台 / 市域全体
  金額: 初期 ¥25,000,000（5年償却で年 ¥500万） + 月額 ¥9,600,000/年
        = 年間約 ¥1,460万
```

**Phase 1 の金額を意図的に低く設計している**のは、単年度予算で決裁可能な金額帯に収め、次年度の本格導入を予算要求へ載せる時間を作るため。

## 2. 買い手のROI

### 2.1 削減される費用（仮説）

| 費目 | 現行 | 導入後 | ステータス |
|---|---|---|---|
| 漏水調査委託費 | 音聴棒・相関式探知機による全域巡回を数年周期で実施 | **AIが示した箇所のみを重点調査**（全域巡回の頻度を下げる） | **要検証** — 委託単価（円/km）の実勢値を入手する |
| 破裂事故の対応費 | 緊急出動・道路復旧・断水対応・広報 | Level 1 段階での計画補修に置換 | **仮説** — §3 の定数 `C_burst` |
| 無収水量（漏水損失） | 発見までの期間、漏水が継続 | 検知までの期間を短縮 | **要検証** — 有収率の改善幅は実証データ待ち |
| 熟練調査員の工数 | 音聴調査は熟練者の聴覚に依存 | AIが一次スクリーニングを担い、熟練者は判定困難な箇所に集中 | **未取得** — `docs/field-research.md` の一次情報が必要 |

**【点検コスト1/5削減の試算根拠】**  
本システムの「点検コスト1/5」は、**「従来の音響棒を用いた漏水調査業者への人力徒歩巡回委託コスト（約2,000〜3,000円/km）」** を比較対象とした試算値である。（※IoTセンサー貼付による広域常時モニタリングにより、巡回人件費および現地聞き込み工数を大幅カットすることで実現。仮説段階）。

### 2.2 損益分岐の考え方

Phase 2（1,000台）の年間コストは約 **¥1,460万**。これを上回る削減効果が出るかは、次の式で評価する。

```
年間ROI = (年間の期待回避コスト) − (年間のシステム費用)
        = Σ_年間検知件数 E_avoided(level)  −  ¥14,600,000
```

`E_avoided` は §3 で定義する。**年間の Level 1 検知件数が損益分岐を決める主変数**であり、これは実証事業（Phase 1）で最初に測るべき指標である。

> **ピッチでの注意:** 「点検コストを1/5に削減」（PRD S-5）と言う場合、**比較対象を必ず明示する**。現行の全域音聴巡回と比較するのか、相関式探知機による委託調査と比較するのかで意味が変わる。比較対象が確定するまでは「1/5」を断定形で使わない。

## 3. KPI「推定削減コスト」の算定式

> ダッシュボードの `estimatedCostSavedYen` は**この式のみを根拠とする**。
> 実装上のハードコード（`frontend/src/app/page.tsx` の `MOCK_KPI_DATA`）は本式による算出へ置き換える。

### 3.1 定義

```
推定削減コスト = Σ (検知アラートごとの期待回避コスト E_avoided(level))

E_avoided(0) = 0                                    # 正常。回避コストは発生しない
E_avoided(1) = p1 × (C_burst − C_repair1)           # 微小漏水を計画補修に置換
E_avoided(2) = p2 × (C_burst − C_repair2)           # 進行性漏水を早期補修に置換
E_avoided(3) = C_response_saved                     # 位置の即時特定による復旧時間短縮分
```

### 3.2 定数（すべて仮説。実装では1箇所に定義する）

| 定数 | 値 | 意味 | ステータス |
|---|---|---|---|
| `C_burst` | ¥1,200,000 | 管路破裂1件あたりの総対応費（緊急出動＋道路復旧＋断水対応＋漏水損失） | **仮説** |
| `C_repair1` | ¥185,000 | Level 1 の計画補修費 | **仮説** — `ui-wireframe.md` の見積例と整合させている |
| `C_repair2` | ¥320,000 | Level 2 の早期補修費 | **仮説** |
| `p1` | 0.12 | Level 1 を放置した場合に一定期間内に破裂へ進展する確率 | **要検証** — 最も感度が高い変数。管種・経過年数で層別すべき |
| `p2` | 0.35 | 同 Level 2 | **要検証** |
| `C_response_saved` | ¥150,000 | Level 3 の位置即時特定による復旧時間短縮効果 | **仮説** |

### 3.3 単価あたりの期待回避コスト

| 深刻度 | 計算 | 1件あたり |
|---|---|---|
| Level 0 | — | ¥0 |
| Level 1 | 0.12 × (1,200,000 − 185,000) | **¥121,800** |
| Level 2 | 0.35 × (1,200,000 − 320,000) | **¥308,000** |
| Level 3 | 固定 | **¥150,000** |

### 3.4 デモ既定値での算出例

デモシナリオの検知内訳（Level 1 × 8件、Level 2 × 3件、Level 3 × 1件）を代入すると:

```
8 × ¥121,800  = ¥  974,400
3 × ¥308,000  = ¥  924,000
1 × ¥150,000  = ¥  150,000
─────────────────────────
合計            ¥2,048,400   → 表示「204.8万円」
```

> **注:** 従来ハードコードされていた `1,420,000`（142万円）は算定根拠が存在しなかったため破棄する。上記の式による算出値に置き換える。定数を変えれば表示値も変わるため、**UI には必ず「試算値（前提は `docs/business-model.md`）」の注記を添える**。

### 3.5 実装上の要件

- 定数は**バックエンドの1箇所**に定義し、フロントは算出済みの値を受け取る（定数の二重管理を避ける）。
- KPI はポーリングで取得したアラート実データから算出する。固定値を返さない。
- UI 上に「試算値」であることと前提へのリンクを常時表示する。**根拠のない金額を断定的に見せない。**
