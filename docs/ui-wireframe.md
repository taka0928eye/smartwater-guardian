# [#1] UI-1: 画面設計・ワイヤーフレーム確定

> SmartWater Guardian ダッシュボードの画面構成、共通カラー定義、画面遷移フロー、およびハッカソン本番での3分間デモシナリオを確定する設計ドキュメント。フロントエンド実装（FE-2〜FE-6）の単一仕様源（Single Source of Truth）として使用する。

* **実施日:** 8/10
* **エリア:** design
* **優先度:** **P0**
* **依存タスク:** なし

---

**1. 共通カラー定義（深刻度カラー）**

画面全体のステータス表示、GIS マップ上のノードマーカー（FE-3）、およびアラート一覧・詳細ドロワー内のステータスバッジ（FE-5）で共通利用する。**色の定義とラベル表現は `src/lib/severity.ts` の一箇所に集約**し、コンポーネント間での表記表記ブレを防止する。

| 深刻度 / 状態 | カラーコード | Tailwind クラス例 | 意味・対応方針 |
| --- | --- | --- | --- |
| **Level 1** | `#22c55e`（緑） | `text-green-500` / `bg-green-500` | 微小漏水（経過観察・定期巡回対象） |
| **Level 2** | `#f59e0b`（黄） | `text-amber-500` / `bg-amber-500` | 進行性漏水（早期点検・現地確認推奨） |
| **Level 3** | `#ef4444`（赤） | `text-red-500` / `bg-red-500` | 管路破裂・大漏水（緊急出動・即時隔離） |
| **正常 (Normal)** | `#64748b`（グレー） | `text-slate-500` / `bg-slate-500` | 異常なし（ベースラインレベル） |

**2. レイアウト構成 (ASCII ワイヤーフレーム)**

ハッカソンデモの即応性を最優先とし、ログイン等の認証画面は作成せず**単一ダッシュボード構造**を採用する。

```text
+-----------------------------------------------------------------------------------+
| [Header] SmartWater Guardian | 2026-08-10 10:00 JST | 監視ステータス: 正常稼働中    |
+-----------------------------------------------------------------------------------+
| [KPI 1]          | [KPI 2]          | [KPI 3]          | [KPI 4]      | [KPI 5]    |
| 監視センサー数   | Level 3 件数     | Level 2 件数     | 本日検知数   | 推定削減コスト|
| 1,240 台         | 1 件             | 3 件             | 12 件        | ¥1,420,000 |
+------------------------------------------------------------------+----------------+
| [Left Pane: GIS Map (Leaflet)]                                   | [Right Pane]   |
|                                                                  | Alert List     |
|    (● Level 1)                                                   | +--------------+
|                   (● Level 3 点滅)                               | | SN-002 [L3]  |
|                                                                  | | 10:12 発覚   |
|         (● Level 2)                                              | +--------------+
|                                                                  | | SN-005 [L2]  |
|                                                                  | +--------------+
+------------------------------------------------------------------+----------------+

```

**画面パーツと要件:**

* **Header（ヘッダ）:** 製品ロゴ/名称、リアルタイム時計（JST表示）、全体監視ステータスインジケーター。
* **KPI サマリ (5項目):**
1. 監視センサー数（例: 1,240台）
2. Level 3 件数（赤色強調）
3. Level 2 件数（黄色強調）
4. 本日検知数（累計件数）
5. 推定削減コスト（漏水早期発見による経済効果試算）


* **Left Pane (GIS Map - Leaflet):** 消火栓・センサー設置ノードのプロット。Level 3 ノードは視覚効果として CSS アニメーションで点滅。
* **Right Pane (Alert List):** 検知アラートのタイムライン表示（深刻度降順 ＋ 時刻降順）。

**3. オーバーレイ表示構造（ドロワー ＆ モーダル）**

```text
  【メイン画面】                      【詳細ドロワー (FE-5/FE-4)】            【自動起票モーダル (FE-6)】
+--------------------+               +--------------------------+          +--------------------------+
|  GIS Map / KPI     |               | [SN-002] 詳細解析結果    |          |  AI 自動補修指示書       |
|                    |               | - 配管情報: 鋳鉄管 150mm |          | - 推奨部材: 割Tクランプ |
|  [Alert List]      | -- Click -->  | - 波形/FFTスペクトル     |          | - 概算見積: ¥185,000     |
|   └─ SN-002 [L3]   |               |   (500-1500Hz Peak)      |          | - 作業手順: 1. 現場規制  |
+--------------------+               |                          |          | - 緊急度: High           |
                                     |  [ AI 自動起票 ]  ───────┼─Click─> |                          |
                                     +--------------------------+          |  [ 確定 & 送信 ]         |
                                                                           +--------------------------+

```

* **1. 右スライドイン詳細ドロワー (FE-5 / FE-4)**
* マップ上のノードまたはアラート一覧のカード選択時に右側からスライドイン。
* センサー計測情報、配管基本情報（材質・口径・布設年）を提示。
* **FFT 周波数スペクトルグラフ（FE-4）:** Recharts を用い、漏水特徴帯域（500〜1500Hz）のピークをハイライト表示。
* アクションボタン: 「AI 自動起票」をドロワー下部に配置。


* **2. 中央起票モーダル (FE-6)**
* 「AI 自動起票」押下時に画面中央へモーダル表示。
* Orcarouter（LLM）が自動選定した「適合補修部材（例: 鋳鉄管150mmクランプ）」「概算見積（部品＋工賃）」「作業指示テキスト」のプレビュー表示。
* 「確定」押下により通知アクション（疑似送信）を発火。

**4. 画面遷移フロー**

```text
  [1. ダッシュボード初期画面]
              │
              ├─ (マップ上のノード or アラート一覧カードをクリック)
              ▼
  [2. 右スライドイン詳細ドロワー表示]
              │
              ├─ (FFTスペクトルで 500〜1500Hz ピークを確認後、「AI自動起票」を押下)
              ▼
  [3. 中央起票モーダル表示 (LLM生成結果)]
              │
              ├─ (部材・見積・作業指示書を確認し、「確定」を押下)
              ▼
  [4. 起票完了 & ステータス更新] (Teams/Email 擬似通知＋ノード更新)

```

**ステップ別動作仕様:**

1. **初期状態:** 全体ダッシュボードを表示。5秒間隔のポーリング（またはバックエンド受信）により最新アラートを表示。
2. **詳細確認:** 目的のアラートを選択すると右ドロワーが開く。FE-4 により波形・スペクトルデータが可視化され、AIの漏水判定根拠を提示。
3. **起票実行:** ドロワー内の「AI自動起票」を押すとバックエンド（`services/orcarouter.py`）経由で LLM を呼び出し、構造化された作業指示データを中央モーダルへ描画。
4. **完了処理:** モーダル内で確定を行うと、起票完了ステータスへ更新され、画面上に成功通知メッセージを表示。

**5. 3分間デモシナリオ（タイムライン）**

審査員へ「異常検知 → データ根拠確認 → AIによる作業自動起票」の一連フローを印象付けるための標準実演スクリプト。

```text
[0:00 - 0:45] 導入 & 正常監視表示
 ├── 画面全体の提示（自治体オペレーションセンター風 UI）
 └── KPI サマリ（監視台数、試算コスト削減額）と GIS マップ上の正常ノード状態を解説

[0:45 - 1:30] 漏水検知 & アラート発生
 ├── 疑似データ投入（Level 3 大漏水発生）
 └── GIS マップ上の消火栓ピンが赤色点滅、右側アラート一覧最上部に新規通知がスタック

[1:30 - 2:15] 波形・スペクトル解析表示
 ├── アラートをクリックし、右スライドイン詳細ドロワーを展開
 └── FFT スペクトルグラフを提示（500〜1500Hz 帯域の特有エネルギーピークによる漏水判定根拠を説明）

[2:15 - 3:00] AI 自動起票 & エージェント連携
 ├── 「AI 自動起票」ボタンを押下
 └── LLM (Orcarouter) が管路台帳と照合して生成した「推奨部材・概算見積・作業指示書」を中央モーダルで提示し実演終了

```
