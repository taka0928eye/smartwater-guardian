**1. 共通カラー定義（深刻度カラー）**

画面全体のステータス表示、GIS マップ上のノードマーカー（FE-3）、およびアラート一覧・詳細ドロワー内のステータスバッジ（FE-5）で共通利用する。**色の定義とラベル表現は `src/lib/severity.ts` の一箇所に集約**し、コンポーネント間での表記表記ブレを防止する。

深刻度は **Level 0〜3 の4段階**（PRD §2）。Level 0（正常）を独立した深刻度として持つことで、「異常なし」と「AIだけが検知できる微小漏水（Level 1）」を画面上で明確に区別する。**この区別がデモの訴求の核心**であり、Level 1 を緑＝正常系の色に置いてはならない。

| 深刻度 / 状態 | カラーコード | Tailwind クラス例 | status値 | 意味・対応方針 |
| --- | --- | --- | --- | --- |
| **Level 0** | `#64748b`（グレー） | `text-slate-500` / `bg-slate-500` | `normal` | 異常なし（ベースライン） |
| **Level 1** ★ | `#84cc16`（黄緑） | `text-lime-500` / `bg-lime-500` | `watch` | **微小漏水（AI検知）** — 人間には無音・水圧変化なし。**本プロダクト唯一の差別化領域** |
| **Level 2** | `#f59e0b`（黄） | `text-amber-500` / `bg-amber-500` | `warning` | 進行性漏水（早期点検・現地確認推奨） |
| **Level 3** | `#ef4444`（赤） | `text-red-500` / `bg-red-500` | `critical` | 管路破裂・大漏水（緊急出動・即時隔離） |

**2. レイアウト構成 (ASCII ワイヤーフレーム)**

ハッカソンデモの即応性を最優先とし、ログイン等の認証画面は作成せず**単一ダッシュボード構造**を採用する。

```text
+-----------------------------------------------------------------------------------+
| [Header] SmartWater Guardian | 2026-08-10 10:00 JST | 監視ステータス: 正常稼働中    |
+-----------------------------------------------------------------------------------+
| [KPI 1]          | [KPI 2]          | [KPI 3]          | [KPI 4]      | [KPI 5]    |
| 監視センサー数   | Level 3 件数     | Level 2 件数     | 本日検知数   | 推定削減コスト|
| 1,240 台         | 1 件             | 3 件             | 12 件        | 204.8万円※ |
+------------------------------------------------------------------+----------------+
| [Left Pane: GIS Map (Leaflet)]                                   | [Right Pane]   |
|                                                                  | Alert List     |
|    (● Level 0 グレー)                                            | +--------------+
|                   (● Level 1 黄緑・AI検知)                       | | SN-003 [L1]  |
|                                                                  | | 10:12 AI検知 |
|         (● Level 2)                                              | +--------------+
|                                                                  | | SN-005 [L2]  |
|                                                                  | +--------------+
+------------------------------------------------------------------+----------------+
※ 推定削減コストは試算値。算定式・前提定数は docs/business-model.md §3 に定義し、
   ハードコードせず実データから算出する。UIには「試算値」の注記を常時表示する。

```

**画面パーツと要件:**

* **Header（ヘッダ）:** 製品ロゴ/名称、リアルタイム時計（JST表示）、全体監視ステータスインジケーター。
* **KPI サマリ (5項目):**
1. 監視センサー数（例: 1,240台）
2. Level 3 件数（赤色強調）
3. Level 2 件数（黄色強調）
4. 本日検知数（累計件数）
5. 推定削減コスト（**試算値**。`docs/business-model.md` §3 の算定式で実データから算出。固定値を表示しない）


* **Left Pane (GIS Map - Leaflet):** 消火栓・センサー設置ノードのプロット。**Level 1 ノードは黄緑で「AI検知」ラベル付き**（デモの主役）。Level 3 ノードは視覚効果として CSS アニメーションで点滅。
* **Right Pane (Alert List):** 検知アラートのタイムライン表示（深刻度降順 ＋ 時刻降順）。

**3. オーバーレイ表示構造（ドロワー ＆ モーダル）**

```text
  【メイン画面】                      【詳細ドロワー (FE-5/FE-4)】            【自動起票モーダル (FE-6)】
+--------------------+               +--------------------------+          +--------------------------+
|  GIS Map / KPI     |               | [SN-003] 詳細解析結果    |          |  AI 自動補修指示書       |
|                    |               | - 配管情報: 鋳鉄管 150mm |          | [AI生成] ← source バッジ |
|  [Alert List]      | -- Click -->  | - FFTスペクトル          |          | - 推奨部材: 割Tクランプ |
|   └─ SN-003 [L1]   |               |   (500-1500Hz Peak)      |          | - 概算見積: ¥185,000 ※   |
|      AI検知        |               |                          |          | - 作業手順: 1. 現場規制  |
+--------------------+               |  [ AI 自動起票 ]  ───────┼─Click─> | - 緊急度: Medium         |
                                     +--------------------------+          | ── API原価: ¥X.XX ──     |
                                                                           |  [ 確定 & 送信 ]         |
                                                                           +--------------------------+
   ※ 概算であり正式見積ではない旨を常時表示

```

* **1. 右スライドイン詳細ドロワー (FE-5 / FE-4)**
* マップ上のノードまたはアラート一覧のカード選択時に右側からスライドイン。
* センサー計測情報、配管基本情報（材質・口径・布設年）を提示。
* **FFT 周波数スペクトルグラフ（FE-4）:** Recharts を用い、漏水特徴帯域（500〜1500Hz）のピークをハイライト表示。
* アクションボタン: 「AI 自動起票」をドロワー下部に配置。


* **2. 中央起票モーダル (FE-6)**
* 「AI 自動起票」押下時に画面中央へモーダル表示。
* Orcarouter（LLM）が自動選定した「適合補修部材（例: 鋳鉄管150mmクランプ）」「概算見積（部品＋工賃）」「作業指示テキスト」のプレビュー表示。
* **生成元バッジを必ず出し分ける**（PRD NFR-5）: `source="llm"` →「AI生成」／ `source="fallback"` →「規定ルールによる自動算出」。**障害時でも生成元について嘘をつかない。**
* **「概算であり正式見積ではない」注記を常時表示**する。
* **脚注に実測API原価を表示**（PRD FR-6）: 「本起票のAPI原価: ¥X.XX（モデル: ◯◯）」。`source="fallback"` の場合はLLMを呼んでいないため原価は表示しない（推定値で埋めない）。詳細は `docs/llm-cost.md`。
* 「確定」押下により通知アクション（疑似送信）を発火。

**4. 画面遷移フロー**

```text
  [1. ダッシュボード初期画面]
              │
              ├─ (マップ上のノード or アラート一覧カードをクリック)
              ▼
  [2. 右スライドイン詳細ドロワー表示]
              │
              ├─ (FFTスペクトルで 500〜1500Hz ピークを確認後、「AI自動起票」を押下)
              ▼
  [3. 中央起票モーダル表示 (LLM生成結果)]
              │
              ├─ (部材・見積・作業指示書を確認し、「確定」を押下)
              ▼
  [4. 起票完了 & ステータス更新] (Teams/Email 擬似通知＋ノード更新)

```

**ステップ別動作仕様:**

1. **初期状態:** 全体ダッシュボードを表示。5秒間隔のポーリングにより最新アラートを表示。**KPI はポーリング取得したアラート実データから算出**し、固定値を表示しない（`docs/business-model.md` §3.5）。
2. **詳細確認:** 目的のアラートを選択すると右ドロワーが開く。FE-4 によりスペクトルデータが可視化され、AIの漏水判定根拠を提示。
3. **起票実行:** ドロワー内の「AI自動起票」を押すとバックエンド（`services/orcarouter.py`）経由で LLM を呼び出し、構造化された作業指示データを中央モーダルへ描画。**LLM障害時は規定ルールによるフォールバック結果を返し、画面を破綻させない**（PRD NFR-5）。
4. **完了処理:** モーダル内で確定を行うと、起票完了ステータスへ更新され、画面上に成功通知メッセージを表示。

**5. 1分間デモシナリオ（タイムライン）**

審査員へ「**人間には検知不能な段階での**検知 → データ根拠確認 → AIによる作業自動起票」の一連フローを印象付けるための標準実演スクリプト。

> **🎯 主役は Level 1（微小漏水）であり、Level 3（大漏水）ではない。**
> Level 3 は水圧急低下・断水を伴うため、既存の水圧監視や住民通報でも捕捉できる。それを主役に据えると「AIでなければできない」という訴求が成立しない。
> 訴求文は「異常を検知した」ではなく **「人間には無音・水圧変化もない段階で、AIだけが漏水に気づいた」**。

```text
[0:00 - 0:10] 01. 導入 & 無音の異常発生（10秒）
 ├── 画面提示：オペレーションセンター画面（全体が正常な状態）
 └── 【セリフ】「熟練作業員でも聞き取れない水道管の『微小漏水』。
               水圧の変化もゼロ、地上からは完全に無音の最新データを投入します」
               （※裏で事前に用意した --level 1 データをワンクリック発火）

[0:10 - 0:30] 02. Level 1 AI即時検知 ★核心（20秒）
 ├── マップ上のノードが【黄緑】へ変化 ＋ アラート最上部に即座スタック
 ├── KPIパネルの「本日の検知数」「推定削減コスト（例: ¥2,048,400 = 204.8万円）」が跳ね上がる
 └── 【セリフ】「ご覧ください。水圧計は正常のままですが、音響AIだけが異常を検知しました。
               人間には無音の段階で気づける、これがAIである必然性です」

[0:30 - 0:45] 03. 根拠可視化（15秒）
 ├── アラートをクリック ➔ 右スライドイン詳細ドロワーが爆速で開く
 ├── Recharts による FFT スペクトルグラフ（500〜1500Hzの異常ピーク）を提示
 └── 【セリフ】「500〜1500Hz帯の波形エネルギーピークと布設年数から、AIが漏水と判定しています」

[0:45 - 1:00] 04. AI自動起票 & 収支・原価の提示（15秒）
 ├── ドロワー内の「AI自動起票」ボタンを押下
 ├── LLM (Orcarouter) 生成の「推奨部材・概算見積・作業指示」モーダルが表示される
 └── 【セリフ】「『AI自動起票』を押すと、LLMが管路台帳から最適な補修部材と概算見積を自動生成。
               1起票あたりのAPI原価もわずか【¥X.XX】。現場の調査・手配コストを9割削減します」
               （※画面を強調してフィニッシュ）
```
