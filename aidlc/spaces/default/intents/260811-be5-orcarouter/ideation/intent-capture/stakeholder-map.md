# Stakeholder Map — BE-5: services/orcarouter.py によるLLM自動起票の実装

## 主要ステークホルダー

| ステークホルダー | 関心事 | 役割（決定権者 / 影響力） | Source |
|---|---|---|---|
| 開発チーム（FE/BE） | BE-5 を Issue の受け入れ条件どおりに実装し、カバレッジ 80% 以上・lint・テストを満たす | 実装判断（スコープ・優先度の実行判断） | [Q7] |
| PRD / GitHub Issue（要件定義者） | FR-3 / FR-4 / FR-6 / NFR-4 の要件を定義 | 決定権者（要件は決定済み） | [Q7] |
| デモ評価者（8/15） | 機能の完成度・デモでの動作確認 | 最終確認（レビュー評価者） | [Q7] |
| 運用スタッフ（エンドユーザー） | 漏水アラート対応時の起票作業を自動化・省力化 | 影響力（受益者） | [Q4] |

## 決定権者 vs 影響力者

- **決定権者**: PRD / GitHub Issue が要件を決定済み。開発チームが実装上の判断を行う。 [Q7]
- **影響力者**: 運用スタッフ（受益者）、デモ評価者（最終確認）が意思決定に影響を与える。 [Q7]

## コミュニケーション要件

- 特になし。個別 Issue ベースで進捗管理し、定例レビュー等の報告体制は定義しない。 [Q8]
