# Personas — FE-7 KPIサマリの実データ連携と「試算値」注記

> 出典: business-overview / Issue #19 / requirements.md。一次ソースは GitHub Issue #19（ユーザー指示）。
> Q1 確定（A）: オペレータ一次 + デモ評価者二次の 2 ペルソナ。デモ評価者はレビュアー視点として参照のみ。

## P1. 水道事業者オペレータ（監視担当）— 一次

| 項目 | 内容 |
|---|---|
| 名前（仮） | 佐藤 健一（41 歳） |
| 役割 | 水道事業者の配水・給水監視オペレータ。朝・夕のシフトでダッシュボードを監視する |
| 業務ゴール | 漏水の早期検知と対応優先度の把握。KPI で事業の健全性（センサー網・リスク分布・削減効果）を定期的に確認する |
| ペインポイント | 根拠のない数値（モック）を断定的に見せられると誤った判断・誤報告の恐れがある。バックエンド停止中に画面が白紙になると監視が継続できない |
| コンテキスト | デスクトップ PC でダッシュボードを閲覧。地図・アラート一覧と合わせて KPI サマリを一目で確認する。専門用語（Level 1〜3）を理解している |
| 優先度 | **Must-have（一次顧客）** |

## P2. デモ評価者 — 二次（レビュアー視点として参照のみ）

| 項目 | 内容 |
|---|---|
| 名前（仮） | デモ受領者（自治体 / 事業者関係者） |
| 役割 | 8/10〜8/15 のデモで本システムの成果を評価する最終確認者 |
| 業務ゴール | 実データで KPI が正しく表示されること・試算根拠が明示されていることを確認する |
| ペインポイント | 実データのないデモで「見せかけの数値」と受け取られると信頼を損なう。「試算値」の明示がなければ金額を断定と誤解される恐れがある |
| コンテキスト | デモ時にのみ操作。オペレータほどの詳細な専門知識は持たない場合がある |
| 優先度 | 二次（参照のみ。本スコープのストーリーの主語にはしない） |

## ペルソナ関係と優先順位

- **P1 オペレータ**が本スコープのストーリーの主語。KPI 表示の変更は P1 の監視体験に直接影響する。
- **P2 デモ評価者**は、デモ成功（MOCK 撤去・試算値注記・スケルトン）を受入条件として検証する視点で参照する。ストーリーの主語にはしない。
- **開発者はペルソナ外のアクター**（内部品質ストーリー US-4「`SeverityLevel` 単一ソース化」の主語）。エンドユーザーのペルソナではなく、2 ペルソナ構成と区別する（design agent 補足提案）。
